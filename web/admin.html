Policy store

The account page, the policy panel, and the sections below act on the active store. Starting a flow activates and resets flow scratch, and running a flow step activates it. Only an explicit control goes back to saved policy: the button below, or the one beside the badge on the demo home.

Kept in the saved store: delegations, app grants, rules, settings, the Imaging Server's signing key, and token records, as SHA-256 hashes. Kept only in memory: sign-ins in progress, authorization codes, account sessions, used assertion IDs, the demo clock, and backend client keys, which are generated at startup.

Decision service

During an outage, requests that need a decision get a 503. Requests the proxy answers from a signed URL keep working.

Revocation

  • Ends every access and refresh token in the active store, while a signed URL or cached decision already issued keeps working until it expires, which is the revocation window.
  • Clears every decision the proxy has cached, so its next request for each goes back to the Imaging Server.
  • Replaces the Imaging Server's signing key and retires the old one. This screen tells this demo's proxy to refetch its keys, so every signed URL already issued loses the instant path at once here. A proxy that isn't told learns from the Imaging Server's public keys within 60 seconds, when its copy expires. After that, each request on an old URL goes to the Imaging Server, and a currently valid token still gets what policy allows.
