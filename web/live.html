What these terms mean
Session
One run of a flow. Everything it causes shares a session, carried across services in a baggage header.
Trace
One user action: a step. Its ID travels between services in the W3C traceparent header.
Span
One timed piece of work, nested under the work that caused it.
Action
What the user did, with the choices they made.
Client and server
The two sides of one HTTP call. → marks the caller's side. The row nested right under it, marked ↳, is the same call as the receiving service saw it. Both are shown because each side records its own headers and timing.
Check
An in-memory decision with no network call, such as one fast-path test or one policy evaluation. Green passed. Amber didn't, which isn't always an error: a failed fast-path test just means the proxy asks.
Preview
A short reading of one span, opened by clicking its row or pressing Enter or Space on it. It shows the fields that matter for that kind of event, such as a token request's grant, or a retrieval's signed context and parts.
Full exchange
One HTTP call's headers and bodies, in a new tab. ↗ on a row opens it.
HTTP log
Every HTTP call in a trace, in a new tab, each with its full exchange. You can filter it by any text.

Text bodies are kept up to 256 KB and binary bodies to 2 KB, with the true size shown. Clicking a row, or scrolling up, turns off Follow newest so the page holds still. Tick it to return to the newest session.

Tokens, codes, and PKCE verifiers appear only as sha256: prefixes, so you can match them across services without seeing them. Session cookies and client assertion signatures aren't recorded. Orthanc is shown as HTTP calls to it. The S3 bucket and static files are read through a storage client, so they appear as spans without HTTP exchanges.
